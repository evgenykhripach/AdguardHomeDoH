# Добавление новых зависимостей сервиса

Allowlist версионируется. Нельзя добавлять общий CDN или крупный shared-домен только
потому, что он встретился один раз: это отправит через VPS чужой трафик.

1. Воспроизведите конкретную функцию на тестовом клиенте из РФ.
2. Снимите только имена DNS и TLS SNI без payload, токенов, URL-параметров и query
   logs. Браузер DevTools показывает host зависшего запроса; для приложений полезны
   краткий `tcpdump` заголовков DNS/TLS или журнал ошибок уровня warning.
3. Убедитесь, что соединение использует TCP 443 и домен открывается непосредственно
   с VPS. Для hardcoded IP/UDP этот Smart DNS не подходит.
4. Выберите минимальную запись: `host.example.,fqdn` для одного хоста или
   `example.com.,suffix`, только если весь registrable domain принадлежит сервису.
5. Добавьте строку в один групповой CSV и в том же порядке в `domains/domains.csv`.
6. Запустите `python3 -m unittest discover -s tests -v`, установите новую генерацию
   и проверьте login, API, SSE/WebSocket и оригинальный сертификат сайта.
7. При регрессии выполните `rollback.sh` и удалите неподтверждённую запись.

Пересматривайте список после изменений сервисов. Новые домены не добавляются по
непроверенным публичным спискам: сначала подтверждается назначение и SNI.

# Прямая загрузка Apple-профиля с корневого HTTPS-адреса

Дата: 2026-08-07

## Цель

Сделать Apple-профиль доступным непосредственно по адресу
`https://dns.pressroll.ru/`. Переход по этому адресу должен начинать загрузку
`dns.pressroll.ru.mobileconfig`, а существующий DoH endpoint
`https://dns.pressroll.ru/dns-query` должен продолжить работать без изменений.

## Выбранный подход

Используется небольшой воспроизводимый patch поверх закреплённого исходника
`mosajjal/sniproxy` v2.3.0, commit
`5be8145042cb3a87b76993d43187b07daa254dff`.

Встроенный DoH-сервер уже завершает TLS для `dns.pressroll.ru` и обслуживает
`/dns-query`. Patch добавляет в тот же HTTP mux обработчик корневого пути `/`.
Это сохраняет существующего владельца TCP 443, GeoIP ACL, исходный IP клиента,
DoT и прозрачное SNI-проксирование остальных доменов. Новые демоны и публичные
порты не создаются.

Рассмотренные альтернативы отклонены:

- перенаправление на GitHub Raw не даёт загрузку непосредственно с указанного
  адреса и создаёт внешнюю зависимость;
- отдельный TLS reverse proxy и новый DoH backend усложняют схему TCP 443 и
  сохранение исходного IP для GeoIP;
- перенос DoH на другой hostname нарушает уже выданный Apple-профиль и
  существующие клиентские настройки.

## Артефакты и сборка

- Исходный профиль остаётся в
  `profiles/dns.pressroll.ru.mobileconfig`.
- Renderer копирует профиль в каждое версионированное поколение конфигурации.
  Активный путь на сервере:
  `/etc/sniproxy/current/dns.pressroll.ru.mobileconfig`.
- Systemd unit передаёт путь через переменную окружения
  `SNIPROXY_APPLE_PROFILE`. Patch не содержит домена или абсолютного пути,
  зашитого в код.
- Patch хранится в репозитории отдельно от upstream source. Сборка проверяет
  checksum закреплённого source archive и checksum patch-файла, применяет patch
  без fuzz и прекращается при любом несовпадении.
- Бинарник по-прежнему собирается из закреплённого commit и закреплённой версии
  Go. Установщик проверяет SHA-256 перед развёртыванием.

Профиль читается при запуске встроенного DoH-сервера. Если переменная задана,
но файл отсутствует, пуст или не читается, запуск `sniproxy` завершается ошибкой.
Таким образом, обновление не может незаметно опубликовать пустой или чужой файл,
а транзакционный rollback возвращает предыдущее рабочее поколение.

## HTTP-контракт

`GET https://dns.pressroll.ru/` возвращает:

- статус `200`;
- `Content-Type: application/x-apple-aspen-config`;
- `Content-Disposition: attachment; filename="dns.pressroll.ru.mobileconfig"`;
- `Cache-Control: no-store`;
- `X-Content-Type-Options: nosniff`;
- тело, байт-в-байт совпадающее с версионированным профилем.

`HEAD /` возвращает те же метаданные без тела. Иные методы получают `405` и
`Allow: GET, HEAD`. Неизвестные пути по-прежнему получают `404`.

`GET` и `POST /dns-query` сохраняют текущие форматы DoH и не попадают в
обработчик профиля. Имя DNS-запроса и содержимое профиля не записываются в
access/query logs.

## Документация для пользователей

В `docs/client-setup.md` первым способом установки Apple указывается прямая
ссылка `https://dns.pressroll.ru`. Документ описывает загрузку через Safari,
установку в iOS/iPadOS и macOS, предупреждение о неподписанном профиле, удаление
профиля и проверку резолвинга. GitHub Raw остаётся только резервным источником
для диагностики, а не основной пользовательской ссылкой.

## Проверка

Автоматические тесты должны подтверждать:

- renderer включает профиль в поколение и manifest;
- systemd unit передаёт только ожидаемый абсолютный путь;
- сборка применяет patch только к закреплённому source;
- patch регистрирует `/`, не заменяя `/dns-query`;
- отсутствующий профиль блокирует запуск;
- документация содержит публичную корневую ссылку.

Перед production update собирается и проверяется новый Linux amd64 бинарник.
На VPS после транзакционного обновления проверяются:

1. SHA-256 скачанного профиля и repository-файла совпадает.
2. `GET /` и `HEAD /` соответствуют HTTP-контракту.
3. DoH JSON и wireformat на `/dns-query` работают.
4. Plain DNS, DoT и SNI passthrough продолжают работать.
5. TLS-сертификат целевого сайта остаётся оригинальным.
6. GeoIP отказывает нероссийскому адресу.
7. Служба активна, restart counter не растёт, query logs отсутствуют.

При любой ошибке установщик возвращает предыдущее поколение и бинарник. Ручной
rollback остаётся тем же: `/usr/local/libexec/dohdns/rollback.sh`.
